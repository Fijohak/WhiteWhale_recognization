# WhiteWhale_recognization
attempt to explore a method for individual identification of Indo-pacific humpback dolphins.
# 中华白海豚个体识别项目

## 1. 项目简介

本项目面向中华白海豚野外调查影像，目标是从野外调查照片中学习白海豚外观特征，并根据背鳍轮廓、缺口、伤痕和色斑等稳定特征，发现可能属于同一个体的影像记录。

当前数据集已包含部分人工整理的个体分组信息（详见第 5 节）：调查 01、03 中 `80 and above` 与 `70-79` 目录下的子文件夹即为已分好的白海豚个体，因此数据集可以看作**有监督或弱监督数据**。但 `70-79` 目录中仍有尚未归入个体的散图，且背鳍具有左右两面，朝向信息需要在数据中单独标注。项目通过特征学习、相似度计算、检索与聚类辅助研究人员核验、合并或拆分候选分组，逐步建立可信的白海豚个体识别数据库。

---

## 2. 项目背景

中华白海豚个体识别通常依赖背鳍及其周围身体区域的可辨识特征，包括：

* 背鳍整体轮廓；
* 背鳍尖端形状；
* 背鳍后缘的缺口和损伤；
* 身体表面的疤痕、斑点和色素分布；
* 背鳍与身体连接区域的形态；
* 不同时间拍摄时仍然稳定存在的外观特征。

需要特别注意的是，**同一只白海豚的背鳍有左右两侧（两面）**：两侧的缺口、伤痕和色斑分布并不完全相同。识别时必须区分照片朝向——左侧照片与左侧照片直接比较、右侧照片与右侧照片直接比较；跨侧匹配只能作为弱证据，需要人工核验。

但当前数据中**每个个体基本只有一张照片**（少数个体含一次目击的连拍多帧，且已有分组为单张），尚无同一只海豚的左右两侧照片。这意味着：

* 目前不存在"同一体双侧"样本，训练时不必处理跨侧配对；
* 但每张照片的朝向（left / right / unknown）仍必须标注，防止未来补充数据时误把不同侧当作同一只来匹配；
* 单个个体仅一张图意味着训练类别样本数极少（每类 1～少数几张），模型需要利用跨个体的共性特征并依赖迁移学习。

当前数据主要由野外调查照片、视频、处理结果和人工整理文件组成。数据中可能包含日期、调查批次、摄影人员、连续拍摄序列、图像质量区间和候选关系等信息，但缺少可以直接用于监督分类训练的统一个体 ID。

因此，本项目将任务定义为：

> 在没有完整个体标签的条件下，学习白海豚背鳍图像的特征表示，并将可能属于同一个体的拍摄记录组织为候选分组。

## 3. 项目目标

### 3.1 主要目标

1. 整理原始数据集的目录结构和文件元数据；
2. 建立统一的图像索引和数据清单；
3. 从原始照片中提取适合个体识别的背鳍区域；
4. 使用预训练或自监督视觉模型提取图像特征，利用已分好个体的子文件夹作为弱监督标签；
5. 根据特征相似度完成候选个体聚类；
6. 建立人工核验和结果修正流程；
7. 使用核验后的结果逐步优化特征模型；
8. 构建可扩展的白海豚个体检索系统。

### 3.2 非目标

项目第一阶段不追求：

* 完全自动确定所有白海豚的真实身份；
* 在没有人工核验的情况下直接生成最终个体数量；
* 仅根据文件夹编号跨调查推断个体身份；
* 直接使用原始整图完成可靠识别；
* 用模型结果完全替代领域专家判断。

## 4. 任务定义

本项目包含三个相互关联的任务。

### 4.1 图像特征学习

将每张背鳍图像转换为固定长度的特征向量。属于同一只白海豚的图像应当具有较高的特征相似度，不同个体的图像应当具有较低的特征相似度。

### 4.2 候选个体聚类

根据图像或拍摄序列的特征，将数据自动划分为若干候选簇。每个簇代表一个可能的白海豚个体。

聚类算法应允许：

* 自动发现候选簇数量；
* 将无法可靠归类的照片标记为噪声；
* 保留低置信度样本供人工检查；
* 支持后续合并和拆分候选簇。

### 4.3 相似个体检索

输入一张新的白海豚背鳍照片，系统返回特征最相似的若干候选个体，而不是强制输出唯一身份。

示例输出：

| 排名 | 候选个体          |  相似度 | 建议     |
| -- | ------------- | ---: | ------ |
| 1  | Candidate-017 | 0.91 | 建议重点核验 |
| 2  | Candidate-043 | 0.82 | 次要候选   |
| 3  | Candidate-006 | 0.75 | 相似度较低  |

当最高相似度低于设定阈值时，系统应将样本标记为“可能的新个体”或“需要人工判断”。

## 6. 数据使用原则

### 6.1 分层信任目录标签

* `80 and above` 与 `70-79` 中的子文件夹是人工已分好的个体分组，可作有监督/弱监督标签使用；
* 分组编号只在同一调查（01 或 03）内成立，跨调查同名编号不默认对应同一只海豚，需人工核验后才可作全局个体 ID；
* `70-79` 中未归入子文件夹的散图暂不作标签，待归属确认后纳入；
* 低于 70 分的区间以及 `MO`/`RAY`/`DEREK`/`miscellaneous`/`nn relationship` 等目录暂不用于个体标签。

### 6.2 避免重复数据

压缩文件和解压后的目录可能包含相同数据。数据索引阶段应进行文件哈希或图像相似度检查，避免重复统计和重复训练。

### 6.3 保留原始数据

原始数据目录保持只读。所有清洗、裁剪、重命名和整理结果保存在独立目录中，避免破坏原始材料。

### 6.4 保留数据来源信息

每张处理后的图片都应能够追溯到：

* 原始文件路径；
* 调查日期；
* 拍摄批次；
* 连续拍摄序列；
* 原始候选分组；
* 图像质量区间；
* 处理方式；
* 人工核验状态。

## 7. 数据处理流程

### 阶段一：数据盘点

对数据集进行整体统计，包括：

* 图片总数；
* 视频和非图片文件数量；
* 调查日期和批次数量；
* 文件格式和分辨率分布；
* 各目录中的图片数量；
* 重复文件数量；
* 无法读取或损坏的文件数量；
* 不同质量区间的数据量；
* 每个连续拍摄序列的图片数量。

输出统一的数据清单，例如：

| 字段            | 含义         |
| ------------- | ---------- |
| image_id      | 项目内部唯一图片编号 |
| original_path | 原始文件路径     |
| session_id    | 调查日期或调查批次  |
| sequence_id   | 连续拍摄序列编号   |
| source_group  | 原始候选分组     |
| quality_band  | 原始质量或评分区间  |
| side          | 左侧、右侧或未知   |
| crop_path     | 背鳍裁剪图路径    |
| review_status | 人工核验状态     |

### 阶段二：数据清洗

需要识别和处理：

* 无法打开的文件；
* 完全重复的图片；
* 高度相似的连续重复帧；
* 没有出现白海豚的图片；
* 背鳍不可见或目标过小的图片；
* 严重模糊或过度曝光的图片；
* 包含多只白海豚但无法确定目标的图片；
* 左右侧无法判断的图片。

低质量图片不一定永久删除，可以单独保留，等待后续模型能力提高后再次处理。

### 阶段三：背鳍区域提取

个体识别应主要基于背鳍及其附近身体区域，而不是整张海面照片。

第一阶段可以采用人工或半自动方式完成裁剪。裁剪区域应：

* 完整保留背鳍尖端；
* 完整保留背鳍前缘和后缘；
* 保留背鳍下方少量身体区域；
* 保留部分周围上下文；
* 尽量减少海面、船只和远处背景；
* 避免将背鳍边缘裁掉。

当项目积累足够的检测标注后，可以训练自动背鳍检测模型，替代人工裁剪。

### 阶段四：朝向识别

白海豚左右两侧的缺口、疤痕和色斑并不完全相同，因此需要记录图像朝向：

* left：展示个体左侧；
* right：展示个体右侧；
* frontal/rear：正面或背面角度；
* unknown：无法确认。

第一阶段建议分别对左侧和右侧照片进行特征比较，避免模型错误地将左右侧视为完全相同。

## 8. 模型方案

### 8.1 基线方案

首先使用已有预训练视觉模型提取背鳍特征，不对模型进行专门训练。

基线流程：

```text
背鳍裁剪图
→ 预训练视觉编码器
→ 特征向量
→ 特征标准化
→ 相似度计算
→ 聚类和检索
```

基线方案用于判断：

* 数据是否具有可区分的个体特征；
* 现有预训练模型是否能区分背鳍形态；
* 聚类结果是否主要受到背景和拍摄条件影响；
* 后续是否有必要进行自监督微调。

### 8.2 自监督学习

在没有个体标签的情况下，使用全部合格背鳍图片进行自监督训练。

模型通过同一张图片的不同增强视图学习稳定特征。增强方式应尽量模拟真实拍摄变化，同时避免破坏个体识别特征。

推荐增强：

* 轻微缩放和裁剪；
* 小角度旋转；
* 亮度和对比度变化；
* 轻微颜色变化；
* 轻微模糊；
* 轻微分辨率变化。

谨慎使用：

* 水平翻转；
* 大角度旋转；
* 大面积遮挡；
* 严重模糊；
* 会删除背鳍尖端或后缘的随机裁剪；
* 会改变背鳍轮廓的几何形变。

### 8.3 序列级特征

连续拍摄的多张图片通常属于同一次目击记录。直接对单张图片聚类，模型可能只学会识别连续帧，而无法完成跨日期识别。

因此需要建立序列级表示：

```text
连续拍摄序列
→ 每张图片提取特征
→ 排除低质量帧
→ 特征平均或加权融合
→ 得到序列级特征
```

最终优先比较不同日期或不同调查批次之间的序列特征。

### 8.4 无监督聚类

聚类阶段不预先假设白海豚个体数量。

聚类结果应包含：

* 高置信度候选簇；
* 低置信度边界样本；
* 无法归类的噪声样本；
* 簇间相似度；
* 每个簇的代表图片；
* 每个簇包含的调查日期和拍摄序列。

聚类算法的具体选择将在实验阶段比较，重点考察：

* 是否需要预先指定簇数量；
* 对异常样本的处理能力；
* 对参数变化的稳定性；
* 是否容易出现过度合并；
* 是否容易将同一个体拆成多个簇。

## 9. 人工核验流程

模型聚类结果不直接作为最终个体身份，需要经过人工核验。

人工核验应重点检查：

* 背鳍轮廓是否一致；
* 缺口的位置、大小和形状是否一致；
* 伤痕和色斑是否一致；
* 图像是否展示同一侧身体；
* 是否存在明显不同的背鳍特征；
* 是否因背景、日期或光线相似而被错误聚类；
* 是否存在两个候选簇实际属于同一个体。

核验操作包括：

* 确认候选簇；
* 拆分混合簇；
* 合并重复簇；
* 标记无法确定的样本；
* 标记疑似新个体；
* 记录判断依据；
* 记录核验人员和核验时间。

建议每次人工修改均保留版本记录，避免覆盖历史判断。

## 10. 伪标签迭代

人工确认后的候选簇可以作为伪标签，用于进一步训练个体特征模型。

迭代流程：

```text
预训练特征
→ 第一次聚类
→ 人工核验
→ 生成伪标签
→ 特征模型微调
→ 重新提取特征
→ 重新聚类
→ 再次人工核验
```

随着可靠伪标签数量增加，可以逐步从完全无监督方法过渡到弱监督或半监督方法。

高置信度样本优先用于训练，低置信度样本继续保留在待核验集合中。

## 11. 评价方案

虽然主要训练过程是无监督的，但仍需要建立少量人工确认的评估集。

评估集应尽量包含：

* 多个已确认个体；
* 每个个体的多个拍摄序列；
* 不同调查日期；
* 不同拍摄角度；
* 不同光照和海况；
* 左侧和右侧照片；
* 不同图像质量等级。

### 11.1 检索评价

用于判断输入一张照片后，正确个体是否出现在候选列表中。

主要指标：

* Rank-1；
* Rank-5；
* Mean Average Precision；
* 同个体和不同个体相似度分布。

### 11.2 聚类评价

在人工确认子集上评价：

* 聚类纯度；
* 调整兰德指数；
* 标准化互信息；
* 同一个体被拆分的比例；
* 不同个体被错误合并的比例；
* 噪声样本比例。

### 11.3 开放集评价

系统需要判断新照片是否可能属于数据库之外的新个体。

重点关注：

* 已知个体误判为未知的比例；
* 未知个体错误匹配到已知个体的比例；
* 不同相似度阈值下的精确率和召回率；
* 高风险错误合并数量。

在保护动物个体识别中，将两个不同个体错误合并可能直接影响种群数量估计，因此需要优先控制错误合并风险。

## 12. 实验阶段规划

### 第一阶段：数据理解与最小基线

目标：

* 完成原始数据盘点；
* 建立统一数据清单；
* 选择一批清晰背鳍照片；
* 完成人工裁剪和朝向标记；
* 使用预训练模型提取特征；
* 完成第一次相似度检索和聚类。

建议数据规模：

* 300～1000 张清晰照片；
* 尽量覆盖多个调查日期；
* 保留连续拍摄序列信息。

主要交付物：

* 数据清单；
* 背鳍裁剪数据；
* 图像和序列特征；
* 候选聚类结果；
* 每个簇的可视化拼图；
* 基线实验报告。

### 第二阶段：自监督特征优化

目标：

* 使用全部合格背鳍图片进行自监督微调；
* 比较微调前后的检索和聚类结果；
* 分析模型是否主要关注背鳍轮廓；
* 优化数据增强和图像裁剪策略。

主要交付物：

* 自监督特征模型；
* 特征可视化结果；
* 聚类参数对比；
* 错误案例分析。

### 第三阶段：人工核验与伪标签训练

目标：

* 建立人工核验工作流；
* 确认一批高可信个体；
* 生成第一版伪标签；
* 使用伪标签进行度量学习或对比学习；
* 提升跨日期个体检索能力。

主要交付物：

* 候选个体数据库；
* 人工核验记录；
* 伪标签版本；
* 优化后的特征模型；
* 检索评价报告。

### 第四阶段：自动化系统

目标：

* 训练背鳍检测模型；
* 自动完成目标裁剪；
* 自动提取特征；
* 自动返回候选个体；
* 支持新个体标记和人工确认；
* 建立可持续更新的个体数据库。

主要交付物：

* 背鳍检测模块；
* 个体特征提取模块；
* 候选检索模块；
* 人工核验界面；
* 数据库更新流程；
* 完整实验文档。

## 14. 风险与应对措施

### 14.1 原始候选分组并非真实身份

应对方式：

* 将其作为弱标签或参考信息；
* 不作为最终训练标签；
* 通过跨日期匹配和人工核验确认。

### 14.2 模型根据背景而非背鳍聚类

应对方式：

* 使用背鳍裁剪图；
* 减少海面背景；
* 使用跨日期评估；
* 检查模型关注区域；
* 比较同背景不同个体的特征。

### 14.3 连续帧造成数据泄漏

应对方式：

* 将连续拍摄序列视为不可拆分的数据单元；
* 训练集和测试集按序列或日期划分；
* 不允许同一连拍组同时出现在训练和测试中。

### 14.4 左右侧照片错误匹配

应对方式：

* 记录图像朝向；
* 分别建立左右侧特征；
* 不默认使用水平翻转；
* 对跨侧匹配设置更严格的人工核验规则。

### 14.5 聚类结果过度合并

应对方式：

* 使用保守的相似度阈值；
* 优先保证候选簇纯度；
* 将不确定样本标记为噪声；
* 对高风险合并进行人工复核。

### 14.6 聚类结果过度拆分

应对方式：

* 比较不同日期的序列级特征；
* 使用多张图片构建个体代表特征；
* 在人工核验阶段支持候选簇合并；
* 使用确认后的伪标签继续优化模型。

### 14.7 个体外观随时间变化

伤痕、缺口和色斑可能随时间发生变化。系统应允许同一个体在不同时间表现出一定差异，并保留日期信息用于长期分析。

## 15. 数据伦理与保护要求

中华白海豚属于保护动物，项目应遵循数据提供方、研究机构和相关保护法规的要求。

需要注意：

* 不公开敏感的调查地点和精确坐标；
* 不公开未经授权的原始调查影像；
* 不将模型用于干扰、追踪或伤害动物；
* 对外发布数据前进行权限和隐私检查；
* 明确模型结果仅作为研究辅助；
* 保留人工审核环节；
* 对错误识别可能造成的种群统计影响进行说明；
* 在论文和项目中正确标注数据来源。

## 17. 项目成功标准

第一阶段成功不以“完全识别全部白海豚”为标准，而以以下结果为标准：

* 数据结构和字段含义得到基本梳理；
* 每张处理图片能够追溯到原始文件；
* 模型能够提取稳定的背鳍特征；
* 同一拍摄序列的图片通常具有较高相似度；
* 部分跨日期的同一个体可以被成功检索；
* 聚类结果明显优于随机分组；
* 模型没有主要按照背景、日期或相机进行聚类；
* 人工能够高效检查和修正候选簇；
* 不确定样本能够被保守地标记为噪声；
* 项目形成可重复、可扩展和可审计的工作流程。

## 19. 方法概述

本项目的核心方法可以概括为：

```text
原始野外影像
→ 数据清洗与元数据整理
→ 背鳍检测或人工裁剪
→ 朝向识别（左右侧）
→ 有监督/弱监督特征学习（以已分好个体的子文件夹为标签，辅以自监督）
→ 图像级特征提取
→ 序列级特征融合
→ 聚类与候选检索
→ 人工核验
→ 伪标签训练
→ 个体数据库持续更新
```

项目最终定位不是完全自动化的身份判定工具，而是一个辅助研究人员整理照片、发现候选匹配、减少人工检索工作量的白海豚个体识别系统。
