# 中华白海豚个体重识别论文研究计划书

**拟投稿期刊：**《自动化学报》  
**建议论文题目：**基于序列约束与质量感知簇级融合的中华白海豚个体重识别方法  
**研究主线：**序列约束度量学习（训练）—抗污染簇级证据融合（推理）—风险受控开放集候选（决策）—人工复核（应用）  
**计划版本：**V1.0  
**计划性质：**研究实施、实验管理与论文写作的一体化执行方案  
**状态说明：**本文中的数值门槛为预注册建议或当前项目记录，不代表尚未完成实验的结果。

## 执行摘要

本计划面向当前中华白海豚个体识别研究原型，目标是在不虚构跨年识别能力、不混用不同评价协议的前提下，将已有的“检测—特征学习—批内聚类—簇级检索—人工审核”工程管线凝练为一篇具有明确方法创新、完整对比实验和可复现证据链的论文。

论文不把 YOLO、ArcFace、MegaDescriptor 或 HDBSCAN 的简单组合视为创新，而是集中解决野外调查影像中三个具有普遍性的困难：第一，相邻连拍帧高度相似，随机划分会造成训练测试泄漏；第二，真实聚类簇可能混入异体照片，简单均值或多数投票缺乏抗污染能力；第三，历史库不完备，系统必须在控制错误接受风险的条件下输出已知、待审和疑似未知三态结果。

建议形成一个统一方法 SQCF（Sequence-aware Quality-guided Cluster Fusion，序列约束质量感知簇级融合），其训练端以跨序列正样本和动态困难负样本增强跨连拍泛化，推理端以图像质量、簇内一致性和稳健截尾策略融合多帧证据，决策端以第一候选分数、投票一致率、候选间隔和簇内离散度完成开放集风险校准。

正式证据由两条互补路线组成：在完整 Happywhale 与 BelugaID 等公开数据上完成可复现的统一协议对比，并在本地中华白海豚数据上完成严格跨序列评估、真实聚类评估、质量分层和人工审核工作量分析。Happywhale 冠军方案只在统一划分和统一指标下作为“冠军派生单模型基线”复现；竞赛排行榜分数仅作为背景资料，不能与自建测试集结果直接横向排序。

## 1. 研究背景与当前基础

### 1.1 当前项目能力

项目已经具备以下可复用基础：

1. YOLOv8 背鳍检测与裁剪流程；
2. 基于 MegaDescriptor-T-224 的 r4 表征模型；
3. ArcFace 分类训练与早期跨组样本挖掘代码；最新日志已确认旧 Triplet 的正负样本挖掘方向有误，因此只能作为待修正的历史实现，不能作为困难负样本有效性的证据；
4. HDBSCAN 批内候选聚类和大簇子簇化；
5. 单图、簇均值、多帧投票和 Top-K 检索能力；
6. 已知、疑似未知、低置信待审三态候选输出；
7. 候选拼图、代表图、人工审核网页和审核记录；
8. 本地数据、Happywhale 分片和 BelugaID 的数据适配与评估框架。

当前项目记录显示，本地数据共涉及 9 个调查批次、约 1040 张影像，其中个体标签、松散候选池和忽略样本的可信度不同。现有 r4 在修正完整连拍序列键后，严格跨串口径仍保持相对 r3 的提升，但旧 Triplet 曾选择最容易正样本和最远负样本，且跨批次身份没有对齐，因此该提升不能因果归于困难负样本；r4 只作为当前生产历史基线。所有早期跨年份匹配候选经人工复核均被撤回，因此目前只能主张“系统能够生成可追溯的跨时间候选”，不能主张已验证跨年自动识别能力。

### 1.2 当前论文证据的主要缺口

1. **创新表达不足。** 当前实现容易被审稿人理解为成熟组件的工程组合。
2. **公开对比不完整。** Happywhale 当前只有一个 2247 张图像的分片，并非完整竞赛数据。
3. **评价协议不一致。** 当前随机 query/gallery 检索与 Kaggle MAP@5、`new_individual`提交协议不同。
4. **BelugaID 指标需重算。** 当前代码的官方正样本索引和过滤后 gallery 局部索引存在不一致风险。
5. **本地跨年真值不足。** 现有数据无法独立支撑跨年开放集识别准确率结论。
6. **簇级方法尚未形式化。** 当前均值和投票缺少明确的质量建模、抗污染机制与置信度定义。
7. **统计证据不足。** 需要多随机种子、按个体或簇的 Bootstrap 置信区间和配对显著性检验。
8. **旧度量损失实现不能复用为证据。** 必须为最难跨序列正样本、最近异体负样本和单序列回退分别增加可核对的单元测试，再进行新训练。

### 1.3 论文定位

论文定位为“面向野外小样本连拍影像的动物个体重识别方法”，中华白海豚是主要应用对象，公开鲸豚数据集用于检验方法的可复现性和跨数据集普适性。

安全题目：

> 基于序列约束与质量感知簇级融合的中华白海豚个体重识别方法

只有在完成身份级已知/未知划分，并获得可靠未知真值后，才使用含“开放集”的题目：

> 面向野外小样本影像的序列约束开放集中华白海豚个体重识别方法

## 2. 研究目标、问题与假设

### 2.1 总体目标

形成一套在野外连拍、小样本、簇污染和历史库不完整条件下仍可可靠运行的中华白海豚个体候选检索方法，并通过公开数据集与本地严格协议验证其有效性、鲁棒性和实际审核价值，完成一篇符合《自动化学报》方法型论文要求的投稿稿件。

### 2.2 可验证研究问题

**RQ1：**在禁止同一连拍序列跨训练、查询和图库的条件下，序列约束度量学习能否提高跨序列个体检索性能？

**RQ2：**当候选簇中混入少量异体照片时，质量感知稳健融合能否比特征均值、最大相似度和多数投票保持更高的检索准确率？

**RQ3：**在固定错误接受率条件下，融合簇级一致性和候选间隔能否提高已知个体召回率，或在召回率不下降时减少人工审核量？

**RQ4：**上述方法是否能在 Happywhale、BelugaID 和本地中华白海豚数据上表现出一致趋势，而不是只对一个小数据集有效？

### 2.3 研究假设

**H1：跨序列训练假设。**与随机正样本或仅 ArcFace 训练相比，优先选择“同个体、不同连拍序列”的困难正样本，可以提升严格跨序列 R@1 和 mAP。

**H2：抗污染融合假设。**在 10%—30% 簇污染下，质量感知截尾融合相对均值、最大值和多数投票具有更小的性能下降。

**H3：风险决策假设。**结合第一候选分数、候选间隔、投票一致率和簇内离散度，可以在 FAR=1% 或 5% 的固定操作点上提高已知个体召回率。

**H4：应用价值假设。**在保持关键候选召回率的前提下，簇级候选可减少需要逐图查看的对象数量，并提供可追溯的成员、分数和投票证据。

## 3. 拟提出的方法

### 3.1 方法总览

输入为一个新调查批次的原始照片，输出为批内候选簇、每簇的历史身份 Top-K、疑似未知标记、代表图以及人工审核所需证据。整体流程如下：

> 原始影像 → 背鳍检测与裁剪 → 图像质量估计 → 序列约束表征模型 → 批内聚类与子簇化 → 抗污染簇级融合 → 开放集风险判定 → 人工确认/不确定/拒绝 → 更新档案库

### 3.2 序列约束度量学习

对每张图像记录个体标签 (y_i)、调查批次 (b_i)、连拍序列 (q_i)、视角 (v_i) 和质量信息 (a_i)。对于锚点 (i)，跨序列正样本集合定义为：

\[
P(i)=\{j\mid y_j=y_i,\ q_j\neq q_i\}
\]

困难负样本集合定义为：

\[
N(i)=\{j\mid y_j\neq y_i\}
\]

当 (P(i)) 非空时，从中选择距离最大的困难正样本，从 (N(i)) 中选择距离最小的困难负样本，构造跨序列度量损失：

\[
L_{seq}=\frac{1}{|A|}\sum_{i\in A}
[d(z_i,z_{p_i^*})-d(z_i,z_{n_i^*})+m]_+
\]

总损失建议为：

\[
L=L_{ArcFace}+\lambda_{seq}L_{seq}
\]

其中，(L_{seq}) 已同时包含最难跨序列正样本和最近异体负样本，不再叠加含义重复的困难负样本损失。只有一个连拍序列的个体继续参与 ArcFace 分类损失，但不参与跨序列正样本损失。训练批次采样器应优先保证一个个体含两个以上不同序列，避免损失项长期失效。

需要验证的关键实现选择包括：跨序列最难正样本与随机正样本、最近异体负样本与随机负样本、固定与动态损失权重，以及单序列个体的回退策略。必须用手工构造的小批次测试证明“正样本距离最大、负样本距离最小”的方向正确，避免继承旧 r4 Triplet 的错误。

### 3.3 图像质量和簇内可靠性

每张图像的基础质量由检测置信度、清晰度、背鳍有效占比和可选的遮挡/视角标签组成。为防止复杂质量网络在小数据上过拟合，第一版采用可解释的归一化质量函数，不新建大型注意力网络。

对簇 (C) 计算特征中心或 medoid，成员一致性为：

\[
r_j=\exp\left(-\frac{d(z_j,z_{medoid})^2}{\tau^2}\right)
\]

图像最终可靠性权重为：

\[
w_j=q_j\cdot r_j
\]

其中 (q_j) 是归一化基础质量。参数归一化方式和 (	au) 只能在训练/校准数据上确定，不能根据测试结果调节。

### 3.4 抗污染簇级证据融合

首先根据簇内距离或可靠性权重剔除最低可靠的少量成员，形成稳健成员集合 (C')。对于候选身份 (k)，单图对该身份图库的得分为：

\[
s(z_j,k)=\max_{g\in G_k}\cos(z_j,g)
\]

簇级加权得分为：

\[
S(C,k)=\frac{\sum_{j\in C'}w_js(z_j,k)}{\sum_{j\in C'}w_j}
\]

簇内成员对候选身份的投票一致率为：

\[
V(C,k)=\frac{\#\{j\in C':\operatorname{Top1}(z_j)=k\}}{|C'|}
\]

必须与下列方法公平比较：单张代表图、特征均值、最大相似度、无权重得分均值、多数投票、质量加权但不截尾、截尾但不加权，以及完整 SQCF。

### 3.5 风险受控的开放集判定

设第一、第二候选簇级得分为 (S_1,S_2)，第一候选投票一致率为 (V_1)，簇内得分离散度为 (D)，构造风险置信度：

\[
R(C)=\alpha S_1+\beta V_1+\gamma(S_1-S_2)-\delta D
\]

系数和阈值在身份隔离的校准集上选择。输出三态：

1. **已知个体候选：**分数和一致性均超过高阈值，进入 Top-K 人工确认；
2. **低置信待审：**证据不足但不能安全判为未知，进入优先审核队列；
3. **疑似未知：**在固定 FAR 操作点下低于拒识阈值，进入新个体复核流程。

“疑似未知”不能自动创建正式身份。正式入库必须经过双人复核，并保留原始路径、批次、序列、算法版本、阈值和审核意见。

## 5. 具体技术路线

### 阶段 0：冻结研究问题和实验协议

**目标：**在继续调参之前先锁定什么问题、用什么数据、按什么指标回答。

**任务：**

1. 冻结四个研究问题和主要/次要指标；
2. 明确本地严格跨序列协议、公开身份隔离开放集协议和官方场景协议；
3. 定义训练、验证、校准、测试四类集合，测试集不得参与阈值选择；
4. 建立实验注册表，记录数据版本、代码版本、模型、种子、参数和输出目录；
5. 清点并冻结所有已知标签问题。

**产物：**`protocol_v1.md`、冻结 manifest、数据哈希、拆分 CSV、实验注册表。

### 阶段 1：数据治理和基线修复

**目标：**得到可信、无泄漏、可重复的基础结果。

**任务：**

1. 完成完整 Happywhale 数据获取和条款记录；
2. 修复 BelugaID gallery 局部索引映射，并用可人工验证的小场景做单元测试；
3. 复核本地 session/sequence/segment 键，检查跨集合同串违规为 0；
4. 为最难正样本、最近负样本和无跨序列正样本回退建立手工可核对测试；
5. 固定检测裁剪和模型预处理，建立图片路径到特征行的可追溯映射；
6. 重跑 DINOv2、MegaDescriptor 零样本和当前 r4 历史基线。

**产物：**数据审计报告、索引回归测试、基线表、可复现命令。

### 阶段 2：序列约束度量学习

**目标：**验证跨序列训练是否比现有训练更能学习个体特征。

**任务：**

1. 实现 sequence-aware batch sampler；
2. 独立实现跨序列最难正样本与最近异体负样本损失，不直接沿用旧 r4 Triplet；
3. 对单序列个体实现显式回退；
4. 运行 ArcFace、普通 Triplet、跨序列正样本、完整方法四级消融；
5. 每个主要配置至少运行 3 个随机种子；
6. 在验证集定参数，在锁定测试集一次性报告。

**产物：**训练曲线、损失消融表、严格跨序列检索表、嵌入可视化和失败案例。

### 阶段 3：质量感知抗污染簇级融合

**目标：**形成论文的主算法模块。

**任务：**

1. 实现清晰度、检测置信度、鳍占比和簇内一致性质量特征；
2. 实现 medoid、一致性权重、稳健截尾和加权身份得分；
3. 比较代表图、均值、最大值、投票、加权和完整 SQCF；
4. 对真实 HDBSCAN 簇、人工确认纯簇和合成污染簇分别评估；
5. 扫描 0%、10%、20%、30% 污染比例，并加入同批次外观相似的困难污染；
6. 报告性能随污染比例的下降曲线。

**产物：**融合方法消融表、污染鲁棒性曲线、真实簇案例、簇内权重可视化。

### 阶段 4：开放集风险校准

**目标：**建立能够解释和复现的已知/待审/疑似未知决策。

**任务：**

1. 按身份划分已知图库身份和未知查询身份；
2. 单独建立校准集，选择 FAR=1% 和 5% 的操作阈值；
3. 比较只用最高相似度、最高分+间隔、最高分+投票、完整风险分数；
4. 报告 AUROC、AUPR、OSCR、TAR@FAR 和审核比例；
5. 检查不同质量、视角、簇大小下的阈值稳定性；
6. 本地无可靠跨年未知真值时，只报告候选和审核工作量，不报告跨年未知识别准确率。

**产物：**ROC/PR/OSCR 曲线、固定 FAR 操作点表、校准曲线和阈值配置。

### 阶段 5：Happywhale 冠军方案统一比较

**目标：**获得方法级而非排行榜级的公平对比。

**任务：**

1. 复现冠军派生 B7 单模型：高分辨率输入、Sub-center Adaptive ArcFace、个体/物种双任务、原图+翻转推理、KNN/logits 融合；
2. 在相同身份拆分、相同 query/gallery 和相同指标下比较；
3. 设置两个输入条件：统一裁剪/统一分辨率的公平模型比较，以及各方法推荐配置的系统性能比较；
4. 条件允许时运行 B6+B7 最小集成作为性能上限；
5. 公开排行榜成绩只放在背景或附录，不与自建测试结果合并排序；
6. 报告参数量、输入分辨率、训练时间和推理吞吐，说明精度—成本权衡。

**产物：**冠军派生基线说明、统一协议主结果表、计算成本表和复现脚本。

### 阶段 6：本地真实应用与人工审核评估

**目标：**证明方法对实际辅助归档有价值，同时严格控制主张边界。

**任务：**

1. 在本地严格跨序列短时间尺度数据上报告检索结果；
2. 按清晰度、遮挡、背鳍大小、左右侧和簇大小分层；
3. 对模型候选进行盲化双人复核；
4. 记录单图审核对象数、簇级审核对象数、Top-K 候选数和审核时间；
5. 分析候选全否决、低质量误匹配、大簇混杂和侧面不一致等失败类型；
6. 不把未确认跨年候选计作正确匹配。

**产物：**本地严格结果表、质量分层表、人工工作量表、典型成功/失败案例。

### 阶段 7：统计、图表、写作与复现归档

**目标：**将代码结果转化为审稿人能够检查的证据链。

**任务：**

1. 对主要指标按个体或簇进行 Bootstrap 95% 置信区间；
2. 对配对 Top-1 结果使用 McNemar 检验，对配对连续分数使用合适的非参数检验；
3. 多重比较时使用 Holm 校正；
4. 固定图表生成脚本，禁止手工修改数字；
5. 完成方法、实验、讨论、引言、摘要的写作顺序；
6. 建立匿名复现包和实验到论文表格的映射表。

**产物：**统计报告、最终图表、论文初稿、匿名复现说明和投稿检查表。

## 6. 实验设计矩阵

### 6.1 数据划分原则

1. 同一张图片不得出现在两个集合；
2. 同一连拍序列不得跨 query/gallery 或训练/测试；
3. 开放集测试中的未知身份不得出现在训练和图库；
4. 参数、融合系数和阈值只在训练/验证/校准数据上确定；
5. 测试结果不得用于二次调整方法；
6. 所有拆分保存显式 CSV，并附违规检查程序和测试；
7. 没有 encounter/sequence 元数据的公开数据必须在局限性中明确说明。

### 6.2 基线模型

| 类别 | 基线 | 目的 |
|---|---|---|
| 通用视觉表征 | DINOv2 零样本 | 检验通用特征下限 |
| 野生动物表征 | MegaDescriptor-T-224 零样本 | 当前强预训练基线 |
| 当前项目 | r4 历史权重与特征 | 生产历史基线；不作为旧困难负样本有效性的证据 |
| 训练消融 | ArcFace、ArcFace+普通 Triplet | 证明序列约束必要性 |
| 冠军派生 | EfficientNet-B7 + Sub-center ArcFace + 双任务 + KNN/logits | 公平比较冠军核心方法 |
| 冠军上限 | B6+B7 最小集成 | 可选性能上限 |
| 簇级推理 | 代表图、均值、最大值、多数投票 | 证明 SQCF 增益 |

### 6.3 核心实验

| 编号 | 实验 | 数据 | 自变量 | 主要指标 | 回答问题 |
|---|---|---|---|---|---|
| E0 | 数据与协议审计 | 全部 | 拆分规则 | 同图/同串违规数 | 结果是否可信 |
| E1 | 序列约束训练消融 | 本地严格集、可用公开集 | 损失与采样器 | R@1、R@5、mAP | H1 |
| E2 | 簇级融合消融 | 纯簇、真实簇 | 融合方式 | 簇级 R@1、mAP | H2 |

### 6.4 指标与统计

**检索指标：**R@1、R@5、R@10、mAP；如复现 Kaggle 官方任务，另报告 MAP@5 和 `new_individual`相关协议结果。

**开放集指标：**AUROC、AUPR、OSCR、TAR@FAR=1%、TAR@FAR=5%、已知/未知混淆和进入待审比例。

**聚类指标：**B-cubed Precision/Recall/F1、ARI、NMI、Purity、噪声率和覆盖率。若真实簇标签不足，清楚区分真实标签指标和人工候选描述统计。

**鲁棒性指标：**不同污染比例下的绝对性能和相对下降率；不同质量、视角和簇大小下的分层结果。

**工程指标：**单图/簇级处理速度、显存、参数量、每批审核对象数、平均 Top-K 数量和审核时间。

**统计要求：**主要训练实验至少 3 个随机种子；按个体或簇 Bootstrap 95% 置信区间；配对检验优先；不只报告最好一次运行。

## 7. 阶段验收与停止条件

下列门槛是建议的项目管理阈值，应在正式主实验前根据小规模预实验调整一次并冻结，冻结后不能根据测试结果追改。

### G0：数据可信门

- 同图泄漏为 0；
- 已知同串跨集合违规为 0；
- 测试身份和训练身份的开放集违规为 0；
- 候选标签未混入监督主测试；
- BelugaID 小场景人工核对与程序索引一致。
- 手工构造批次验证最难正样本、最近负样本和单序列回退方向正确。

任一项不满足，停止主实验并修复数据协议。

### G1：基线可信门

- 基线能够从固定命令重复运行；
- 三次运行的差异有记录；
- 指标能回溯到逐样本预测；
- 与公开论文差异能够由数据、划分、输入或模型版本解释。

### G2：序列训练继续门

缺省建议：严格跨序列主指标相对 ArcFace 基线平均提高至少 2 个百分点，或相对提高至少 5%，且 3 个随机种子方向一致；其他关键指标不能出现超过 1 个百分点的系统性退化。

若不满足，先检查采样器有效率、单序列个体比例、标签噪声和损失权重；仍无稳定提升时，不把序列约束训练写成主创新。

### G3：簇级融合继续门

缺省建议：在 20% 合成污染条件下，完整 SQCF 相对最佳简单融合方法至少提高 5 个百分点，且在无污染条件下退化不超过 1 个百分点；真实 HDBSCAN 簇上趋势应与合成实验一致。

若只在合成污染上有效、真实簇无效，应将其降为鲁棒性附加实验，而不是主创新。

### G4：开放集继续门

在 FAR=5% 条件下，完整风险分数应提高已知召回率；或者在已知召回率基本不变时，将待审比例降低至少 10%。如本地无可靠未知真值，公开数据结果为主，本地只做候选流程展示。

### G5：投稿可行门

满足以下条件后进入《自动化学报》完整写作：

1. 至少一个核心方法模块通过 G2 或 G3，最好两者同时通过；
2. 完整方法在至少两个数据来源上趋势一致；
3. 有冠军派生单模型或等强公开方法的统一协议对比；
4. 有完整消融、置信区间、质量分层和失败分析；
5. 所有论文数字可由脚本从原始预测重新生成。

如只能证明工程流程可运行但没有稳定方法增益，应调整为应用型论文或先补实验，不强行投稿方法型栏目。

## 10. 风险登记与应对

| 风险 | 触发信号 | 影响 | 应对 |
|---|---|---|---|
| 序列训练无稳定提升 | 三种子方向不一致 | 训练创新不成立 | 检查采样器有效率；降为协议贡献 |
| 融合只对理想簇有效 | 真实HDBSCAN簇无增益 | 方法脱离应用 | 加入簇污染建模和子簇质量；必要时缩小主张 |
| Happywhale冠军无法完整复现 | 算力、数据或脚本缺失 | 对比说服力下降 | 保证单B7核心方法；完整集成只作上限 |
| 公共协议与竞赛不同 | 无官方隐藏测试标签 | 不能比较排行榜 | 使用统一自建协议并清楚区分公开成绩 |
| 本地跨年同体为0 | 双审无确认正样本 | 无法证明跨年能力 | 不报告跨年准确率；使用公开开放集验证 |
| 标签噪声较高 | 同组内部特征极不一致 | 训练/测试失真 | 候选标签分层；争议样本敏感性分析 |
| 左右侧差异明显 | 跨侧性能显著下降 | 泛化受限 | 分层报告；研究侧别感知图库或增强 |
| 小样本统计不稳 | CI过宽 | 结论不确定 | 以个体为单位Bootstrap；补数据而非只调模型 |
| 质量权重过拟合 | 仅单一验证集有效 | 方法泛化差 | 优先可解释固定特征；独立校准；跨数据验证 |
| 数据许可限制 | 数据不能公开 | 复现受限 | 公开代码、拆分ID和生成脚本，不分发原始图片 |

## 11. 可复现性、伦理与数据治理

1. 原始图像、个人信息、调查地点敏感信息和模型权重按数据协议管理；
2. Happywhale和BelugaID原始数据不提交到代码仓库；
3. 公开代码不包含真实密钥、Token、Cookie或私人数据盘路径；
4. 论文公开拆分规则、样本ID、随机种子和指标脚本，在许可范围内公开特征或匿名预测；
5. 模型候选不得直接变更正式个体档案；
6. 跨时间确认采用双人复核并记录分歧；
7. 失败案例展示时避免暴露敏感调查位置和未获许可的原图；
8. 所有外部代码明确来源和许可证，无明确许可证的冠军仓库只借鉴思想并独立实现。

## 15. 最终完成定义

本研究计划完成，不以“代码能够运行”为唯一标准，而以下列证据同时具备为准：

1. 数据、标签和划分通过无泄漏审计；
2. Happywhale冠军派生单模型与当前方法在统一协议下完成比较；
3. 序列约束训练或抗污染簇级融合至少有一个形成稳定、可复现的主要增益；
4. 完整消融能够说明每个新增模块的必要性；
5. 开放集结果在固定错误接受率下报告，并区分公开数据真值与本地候选；
6. 本地应用结果经过双人复核，不把候选当成确认身份；
7. 主要结果包含多种子、置信区间、失败分析和计算成本；
8. 论文所有数字由固定脚本生成，能够回溯到原始预测；
9. 完成《自动化学报》双盲稿、复现说明和投稿材料；
10. 独立审查未发现主张越界、协议混用或未说明的数据限制。
