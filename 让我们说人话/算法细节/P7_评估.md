# P7 评估：怎么才算"真的认对了"

> 面向算法/工程人员。本文讲 R@k / mAP 怎么算，以及本项目花大力气设计的三个"防作弊协议"。这是全项目最讲究诚实的地方。

## 一、两个基础指标

代码位置：`src/whitewhale/reid/evaluation.py:13-46`（`recall_at_k`）、`49-71`（`mean_average_precision`）。

**R@k（Recall@k）**：对每个 query，检索 gallery，看正确个体是否出现在**前 k 名**里，取命中率。R@1 最严格——正确个体必须排第一。

**mAP（mean Average Precision）**：把"正确个体在结果列表里的排名位置"加权平均，比 R@k 更细腻地反映"排得有多靠前"。

```python
hits = sum(cand_ids == query_id for cand in indices[:k])
results[k] = hits / n_query
```

## 二、这个项目评估的最大敌人：不是模型，是"作弊"

指标本身很简单，难的是**别让评估自欺欺人**。本项目在数据上踩出了三个坑，各配了一个协议去堵：

### 坑 1：训练泄漏（模型背过题）

**现象**：r3 的训练集见过历史库的部分个体，评估时再考这些个体，等于"背题考试"，分数虚高。

**协议**：训练集和评估集**按个体彻底隔离**（P3 已讲）。r4 的做法——**训练集 = 历史库全部 43 个体，评估集 = 新批次 32 个体（模型从未见过）**。新批次侧从此无泄漏，是"最硬的能力证据"。

### 坑 2：同串连拍平凡命中（相邻帧天然像）

**现象**：同一连拍串里的两张图（连拍号差 ≤2），是同一次目击的相邻帧，相似度天然接近 1。如果把它们一张放 query、一张放 gallery，检索命中是**平凡的**，不能证明"跨目击识别能力"。

E5.1 后续实测：新批次 64 张 query 的命中里，**55% 是这种平凡命中**。

**协议**（两版，代码在 `experiments/eval51_common.py`）：

- **保守口径**：打分前把"与 query 同串的照片"从 gallery 里剔除；
- **串抽样口径**：每串随机抽一半当 query、剩下一半进干扰池，从根上保证 query 和候选永远不同串。

三口径对照（新批次簇级 R@1，r3）：

| 口径 | R@1 | 说明 |
|---|---|---|
| 常规（对半拆） | 0.609 | 含平凡命中，**虚高** |
| 保守（剔同串） | 0.238 | 全部跨串，**下限** |
| 串抽样 | 0.400 | 防平凡又保留串内差异，**折中** |

### 坑 3：弱标签（当年分组 ≠ 真值）

**现象**：评估用"当年分组编号"当个体真值，但那些分组是**候选级、没核验**，组内可能混入异体（实测某组内两张图 cosine 仅 0.15）。

**协议**：诚实标注口径——所有数字都是"**当年分组一致性**"，不是"真识别率"。真正可靠的真值，要等 **3.2 人工评估集核验**。

## 三、r4 的"诚实成绩单"

r3→r4 重训后（E5.2），关键数字（**保守口径，最硬**）：

| 口径 | r3 | r4 | Δ |
|---|---|---|---|
| 保守 · 新批次簇级 R@1 | 0.238 | **0.381** | +0.143 |
| 保守 · 整体簇级 R@1 | 0.364 | 0.477 | +0.113 |
| 保守 · 整体单图 R@1 | 0.311 | 0.377 | +0.066 |

**为什么 0.381 值得信**：这是在"模型从未见过的个体"上、剔除同串连拍后测出来的——它是当前**最可信的跨目击识别能力**。而 0.609 那种"好看"的数字，一半以上是平凡命中堆出来的。

## 四、一个关键诊断：模型其实没"那么弱"

E5.1 的分层诊断给了个反直觉的结论：

| query 与同体最高 cosine | 命中率 |
|---|---|
| (0.6, 0.7] | 0.895 |
| (0.7, 1.0] | **1.000** |

**只要两张照片真的像（cosine > 0.7），模型几乎 100% 认对。** 整体数字低，是因为**37% 的 query 与同体最高 cosine ≤ 0.5**——这些是"当年被分错组的照片"，不是模型眼瞎。

> 这是评估篇最重要的洞察：**低分不全怪模型，很大一部分怪数据标签本身不干净**。这也直接指向 P8 的优化方向——先把数据核验了，指标会显著回升。

## 五、诚实边界（必须写进任何汇报）

1. 以上数字是"当年分组一致性"，非真识别率，最终以 3.2 人工核验为准；
2. 历史库侧（含泄漏）永远不作能力证据；
3. 跨年匹配目前 **0 条确认**——不是模型不行，而是"历史库没核验 + 覆盖不足"共同作用，占比无法区分（未确认 ≠ 不存在）。

> **一句话**：评估的功夫全在"别作弊"上——隔离训练/评估个体、剔除同串平凡命中、认清单标签上限。诚实承认"0 条跨年确认"，比硬凑一个好看的数字更有价值。
