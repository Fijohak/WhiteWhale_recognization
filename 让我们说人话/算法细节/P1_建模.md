# P1 建模：把"认海豚"翻译成数学

> 面向算法/工程人员。本文回答一个问题：这个项目在数学上，到底是个什么问题。

## 一、这不是分类问题

外行一看"认海豚"，第一反应是**图像分类**——每只海豚一个类别，训个分类器完事。

但这里不行，根本原因是**开放集（open-set）**：

- 分类要求"类别数固定"，训练前就得知道一共几类；
- 而我们永远不知道下一个批次会不会冒出一只**从没见过的新海豚**。类别数本身在变，还怎么训分类器？

所以正确建模是 **度量学习（metric learning）/ 检索（retrieval）**：

> 学一个映射 `f`，把图片 `x` 变成向量 `f(x) ∈ R^768`，使得"同一只"的向量**近**，"不同只"的向量**远**。判断身份不靠"套类别标签"，靠"**算距离**"。

这一条，决定了整个项目的技术路线——检测、特征、聚类、匹配，全是为"算距离"服务的。

## 二、核心对象：embedding + cosine 相似度

一张裁剪好的背鳍图，经过 backbone（一个 ViT，MegaDescriptor-T-224），输出一个 768 维向量，叫 **embedding**。

然后做 **L2 归一化**，让每个向量长度都变成 1，全部落到单位球面上。归一化之后：

```
cos(a, b) = a·b / (|a|·|b|) = a·b          （因为 |a| = |b| = 1）
```

**余弦相似度退化成了点积**，落在 [-1, 1]：`1` 表示方向一致（同一只），越接近 `-1` 越不像。

> 项目里你看到的所有"分数"——Top-1 分数 0.866、簇级阈值 0.58、单图阈值 0.50——**本质全都是这个 cosine 值**。理解了它，就理解了所有数字。

## 三、度量空间唯一的目标

训练里的所有花样（ArcFace、triplet、各种采样），只为一个目标服务：

1. **类内紧凑（intra-class compactness）**：同一只海豚的所有照片，向量聚成一团；
2. **类间分离（inter-class separation）**：不同只海豚的团，彼此离得越远越好。

这两条是这个问题的**全部数学诉求**。后面 P2、P3 讲的损失函数和训练技巧，都只是"怎么逼近这个目标"的不同手段——它们的差异只在"用什么样的力，把类内压紧、把类间推开"。

## 四、一个必须提前说破的事实

这个项目真正的难点，**不在模型，在数据**：

- **标签是弱标签**：当年的分组只是"候选"，没核验，组里可能混着错（实测某组内两张图 cosine 只有 0.15）；
- **极端少样本**：很多海豚只有 1 张招牌照，可学的正样本对极少；
- **特征随时间漂移**：海豚会长大、会受伤，背鳍在变，跨年时"同一只"也不那么像了。

这三点决定了：它跟 ImageNet 那种"百万张干净标签"的分类，是**两个世界**。所以你会反复看到——我们一半力气花在"把模型训好"，另一半花在"把数据弄干净、把评估口径摆正"。

## 五、一个由此衍生的、贯穿全文的张力

建模成"算距离"，就必然引出**阈值（threshold）**：距离近到多少，才算"同一只"？

而阈值是从数据分布里标定出来的。数据分布一旦没被真值校准（弱标签、含泄漏、含平凡命中），阈值就标不准。

**这个张力——"模型能算距离，但距离的刻度还没校准"——就是 P7 评估篇、P8 优化篇要反复回到的原点。**
