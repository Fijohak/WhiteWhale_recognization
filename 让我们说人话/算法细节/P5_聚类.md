# P5 聚类：把一堆照片，自动"分堆"

> 面向算法/工程人员。本文讲批内聚类为什么用 HDBSCAN、子簇化在解决什么问题。

## 一、问题：这一批里有几只？

新批次进来后，在"跟历史库对账"之前，先要回答一个更基础的问题：**这批照片里，一共有几只海豚？** 这本质是**聚类**——把长得像的照片归成堆。

## 二、为什么是 HDBSCAN，而不是 KMeans

代码位置：`src/whitewhale/pipeline/archival.py:92-113`。

KMeans 有两大硬伤，在这里都不成立：

1. **KMeans 要预设 K**（分成几类）——但"这批有几只海豚"我们**事先根本不知道**；
2. **KMeans 强制每个点都有归属**——但有些照片是孤立噪声，不该硬塞进任何一堆。

HDBSCAN 解决了这两点：

- **基于密度**，簇的数量**自动决定**，不用预设 K；
- 密度不够的点会**被判成噪声（label = -1）**，这是**合法结果**，不是错误。

配置：`min_cluster_size: 3`（`configs/pipeline.yaml`），即**至少 3 张照片聚在一起才算一个簇**。

```python
clusterer = hdbscan.HDBSCAN(min_cluster_size=args.min_cluster_size)
labels = clusterer.fit_predict(emb)
# labels == -1 的，就是噪声
```

> 直觉：HDBSCAN 找的是特征空间里"密度足够高的团"。海豚连拍（同一次目击）特征高度相似，会自然聚成密集团；零星一张孤图，就落成噪声。

## 三、子簇化：大簇里可能混着好几只

第一层聚类常出一个问题：**长得像的不同海豚，被并进一个大簇**（几十张混在一起）。

于是有了第二层——**子簇化**，代码在 `archival.py:115-137`：

```python
# 对 >= subcluster_min_size(4) 张的大簇，内部再聚一次
sub = hdbscan.HDBSCAN(min_cluster_size=2, min_samples=1).fit_predict(emb[grp_idx])
```

- 拆出来的叫 **纯子簇**（subcluster >= 0）；
- 剩下的叫 **残噪**（subcluster = -1），逐张处理。

**为什么这么干**：审核的单元越小、越纯，人工越容易"一键判定"。一个大杂烩簇，人看着头疼；拆成几个纯子簇，每个都可能是同一只的连拍，点一下"确认"就过了。

> E8 有个漂亮的案例：`20151017 03` 的一个大簇，子簇化后才"显形"出一个被掩盖的历史匹配候选。**拆簇能显形**——大簇会把真正的匹配信号稀释掉。

## 四、噪声和残噪怎么处理：不合并，逐张退化

代码位置：`archival.py:156-172`。

关键原则：**噪声点、残噪点互不相似，不能强行合成一个"噪声簇"**。它们各自独立地走"单图匹配"（退化路径）：

```python
if c == -1 or sc == -1:
    # 逐张独立匹配（单图退化），而非合并成簇
    for _, r in sub.iterrows():
        score_img_to_individual(...)   # 单张直接算
```

**为什么**：簇的意义是"这一堆是同一只，可以多帧投票"。噪声点之间没有这个保证，硬凑成一堆只会引入假的一致性。

## 五、簇的语义红线

最后必须强调（这是项目的纪律）：

> **HDBSCAN 簇 = Candidate Cluster（候选簇），不是个体。**

代码里到处在重申这点（`archival.py:237-238` 的 summary note）。聚类结果只是"看起来像同一只的一堆"，**必须人工审核后才能叫个体**。可能分对，也可能把两只相似的并到一起——这正是后面要有"人工审核网页"的原因。

> **一句话**：HDBSCAN 不用预设 K、允许噪声；子簇化把大杂烩拆纯；噪声逐张退化不合并。聚类给的是"候选堆"，不是"确定个体"。
