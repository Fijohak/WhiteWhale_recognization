# P6 检索与匹配：从"一张图像谁"到"一堆图是谁"

> 面向算法/工程人员。本文讲特征空间里怎么"找人"：Top-K、图→个体聚合、多帧投票，以及阈值从哪来。

## 一、Top-K 检索：一次矩阵乘法

查询一张图，和整个历史库比，本质是**一次矩阵乘法**：

```python
sim = q @ g.T      # (1, D) @ (D, N) → (1, N) 的 cosine
```

代码位置：`src/whitewhale/reid/retrieval.py:11-40`（`cosine_topk`）。

因为所有向量都 L2 归一化了，`q @ g.T` 出来的每个元素就是 cosine 相似度，取最大的 K 个就是 Top-K。

## 二、图 → 个体：一张图怎么对一个"个体"打分

历史库里**一个个体可能有多张照片**。那"查询图和某个个体像不像"，怎么算？

答案是 **max 聚合**——取这张查询图和该个体**所有照片里最像的那一张**的分数：

```python
# score_img_to_individual: 图 → 每个个体 = max over 该个体照片的 cos
for g in unique(gal_ind):
    out[g] = sims[gal_ind == g].max()
```

代码位置：`src/whitewhale/reid/retrieval.py:43-54`。

> 直觉：个体 = 一组照片，"像不像这只" = "有没有哪张特别像"。用 max 而不是 mean，是因为海豚可能只以某个角度/姿态被拍清楚，只要有一张对得上就算对上。

## 三、多帧投票：一堆图，比一张图更可靠

归档时，我们手里往往不是一张图，而是一**簇**图（聚类结果）。这时从"单图判定"升级到"多帧投票"：

代码位置：`src/whitewhale/pipeline/archival.py:173-212`。

```python
# 簇内每张图 → 个体分数；簇级 = 各图对每个个体的分数取 mean
agg = {g: mean([s[g] for s in per_img]) for g in all_g}
# vote1 = 簇内多少比例的图，其首票投给了同一个体
vote1 = mean([max(s, key=s.get) == t1 for s in per_img])
```

两个证据一起看：

- **簇级分数**（mean 聚合后的最高分）；
- **vote1 一致票占比**（簇内图的首选是否一致）。

E5 实测：多帧投票比单图稳定高 8~12pp，03 群簇内 87% 的图把正确个体排第一。

**为什么更可靠**：单张图可能拍糊、拍歪，认错；但一簇连拍里大多数图都指向同一个体，错误会被"投票"稀释掉。这叫"用冗余对抗单点噪声"。

## 四、阈值：从哪来的，怎么用

项目里有两档阈值（`configs/pipeline.yaml`）：

| 阈值 | 值 | 语义 | 出处 |
|---|---|---|---|
| `threshold_cluster` | 0.58 | 簇级匹配门槛 | E5 簇级拒识 FA≤5% 标定 |
| `threshold_image` | 0.50 | 单图/噪声退化门槛 | E4 图级 FA≤5% 区间下限 |

判定逻辑（`archival.py:182-183`、`query.py:202-205`）：

```python
status = "match" if s1 >= threshold_cluster else "suspected_new"
# 查询端：
status = "known" if max_score >= threshold else "unknown"
```

**关键：阈值的语义是"宁可多标疑似，不可错并"。** 0.58 是故意偏保守的——它让更多真匹配被标成"疑似"，但换来"误把不同只当同一只"的概率被压到 ≤5%。因为**错并（把两只当一只）会污染种群统计，是不可接受的**；而"多标几个疑似让人去看"是低成本可接受的。

> 但这里埋着一个大前提（P7 会展开）：这些阈值是**在弱标签、含泄漏的数据上标定出来的**，一旦真值核验完，阈值要**重新标定**。

## 五、查询端的三态输出

查询客户端（`src/whitewhale/query.py:196-228`）把上面一切封装成三态：

- `known`：最高 cosine ≥ 阈值 → 展示 Top-K 候选（仍标注"待人工核验"）；
- `unknown`：最高 cosine < 阈值 → 提示"疑似未知个体（可能新个体）"，仍返回 Top-K 供参考。

默认阈值 0.55（E4 标定区间的中值，`pipeline.yaml` 里 `query.threshold: 0.55`）。

## 六、一条硬约束：查询模型必须与 gallery 同源

代码位置：`src/whitewhale/query.py:65-117`（`_gallery_model` / `resolve_model`）。

查询图和历史库的 embedding 必须**同一个模型**算出来。不同模型的特征分布不同，cosine 不可比。代码里做了双重防护：自动读 gallery 特征旁的 config 匹配模型，显式指定时校验"不同源就拒绝启动"。

> **一句话**：Top-K 是矩阵乘法；图→个体是 max 聚合；多帧投票用"簇内一致性"对抗单图噪声；阈值故意偏保守、错并优先。整条链，都是"算 cosine + 比较 cosine"。
