# P3 训练：怎么把上面这套损失，稳稳地喂下去

> 面向算法/工程人员。本文讲训练这件事本身的工程与策略：两阶段、防泄漏、采样、缓存、增强。

## 一、两阶段训练：先教头，再动身体

训练分两个阶段，代码在 `src/whitewhale/reid/training.py:214-328`（`run_training`）：

| 阶段 | 做法 | 学习率 |
|---|---|---|
| Stage 1 | **冻结 backbone**，只训 ArcFace head | lr_head = 1e-3 |
| Stage 2 | **解冻 backbone**，低学习率微调 | lr_backbone = 5e-6 |

**为什么这么拆**：

- backbone 已经预训练好了，上来就用大学习率动它，会**破坏预训练学到的通用特征**（灾难性遗忘）；
- 而 head 是**随机初始化**的，得先用大学习率让它"上手"；
- 等 head 稳定了，再用**极小学习率**（5e-6，比 head 低 200 倍）轻轻微调 backbone，让它朝"海豚背鳍"这个特定任务偏一偏。

配置值在 `configs/reid.yaml`（`epochs_stage1: 20`、`epochs_stage2: 25`）。

## 二、按个体划分：一条不能破的红线

训练集和验证集的划分，**不是按图片随机切，而是按个体切**：

代码位置：`src/whitewhale/reid/training.py:44-54`（`split_by_individual`）。

```python
# 同一只海豚，绝不既出现在 train 又出现在 val
val_ids = 随机抽 val_n 只海豚
train = 其余海豚的照片
val   = 这些海豚的照片
```

**为什么**：如果同一只海豚的照片一半在训练、一半在验证，那验证时的"认出来"只是"背过这张脸"，是**泄漏（leakage）**，分数虚高，毫无意义。

这就是后来 **r3→r4 重训的核心动机**：r3 的训练集见过历史库的部分个体，导致评估时那些个体是"背题成绩"。r4 把"考的个体"和"训的个体"彻底隔离（详见 P7）。

## 三、跨群 hard negative + 对半采样

在 HN 链路里，有两个关键设计，代码在 `training.py:151-170`（`BalancedGroupSampler`）：

1. **每 batch 强制 01 群、03 群各一半**（带替换重采样）；
2. **负样本 = batch 内跨群 cosine 最高者**（`training.py:186`，`cross = sessions != sessions[i]`）。

**为什么是"跨群"**：01 群和 03 群是两拨**物理上不可能重叠**的海豚，所以"跨群"的任意两张，一定是不同只——**这是唯一零成本就能保证"可靠负样本"的来源**。群内编号相同的（01_02 和 03_02）也不会被误当同一只。

**为什么"对半采样"**：01 群照片少（19 张），如果不强制对半，batch 会被 03 群淹没，跨群负样本就"断供"了，triplet 那一路等于白搭。

> 直觉：triplet 要的是"有难度的负样本"。跨群保证负样本**干净**（不会错标），hard mining 保证负样本**够难**，对半采样保证负样本**恒在场**。三者缺一，triplet 就退化。

## 四、一个容易忽略的工程坑：CPU 解码瓶颈

代码位置：`training.py:123-148`（`DolphinDatasetHn.preload`）。

原图是 3000~4000px 的大图，如果每个 epoch 都现读现解码，**CPU 解码会卡成瓶颈，GPU 空转**。

解决办法：训练前把全部训练图**一次性缩到 256px 放进内存缓存**（约 30MB），之后每个 epoch 只做增强变换，IO 归零。

> 这是一个典型的"训练慢不是 GPU 的锅，是 CPU 喂数据喂不上"的问题。写训练代码时，喂数据的吞吐常常比模型本身更关键。

## 五、数据增强：一条刻意保留的"不用"

增强代码在 `training.py:73-88`：`RandomResizedCrop + RandomRotation(8°) + ColorJitter`。

刻意**不用水平翻转**，理由是：**海豚背鳍左右两侧特征可能不同**，翻转会把左侧背鳍伪装成右侧，破坏标签语义。

> 但注意——后来的实验 E11 实测发现，水平翻转对 r3 特征影响很小（同体相似度仅降 0.030），**翻转增强其实基本安全**。所以这条"不用翻转"是保守的默认，不是铁律，后续可以放开（小概率，如 0.3）。

## 六、验证指标：leave-one-out R@1

训练过程中判断"学得怎么样"，用的是验证集上的 **leave-one-out R@1**，代码在 `training.py:91-104`（`eval_retrieval`）：

```python
sim = feats @ feats.T          # 验证集内两两 cosine
np.fill_diagonal(sim, -1.0)    # 排除自己
top1 = sim.argmax(axis=1)      # 每个图最像的是谁
r1 = (labels[top1] == labels).mean()   # 对的占比
```

r4 训练曲线：预训练基线 val R@1 = 0.740 → 微调后 0.818（best epoch 19，见 `outputs/metric_learning/r4/metrics.json`）。

> **一句话**：两阶段是"别打碎预训练"；按个体分是"别作弊"；跨群 hard negative 是"给 triplet 找干净又难吃的负样本"；内存缓存是"别让 CPU 拖垮 GPU"。这四条，比调超参更重要。
